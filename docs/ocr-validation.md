# 工程0：OCR検証記録

実施日：2026-10-31（日本時間）。関連：[実装 #1](https://github.com/cake2357/house-account-app/issues/1)。

## 実行環境とモデル

- macOS arm64、Python 3.13.14、uv 0.11.25。
- PaddleOCR 3.7.0、PaddlePaddle 3.3.1、PaddleX 3.7.2、CPU推論。
- 検出：PP-OCRv5_server_det、認識：PP-OCRv5_server_rec。
- 公式アーカイブを事前取得し、ファイルごとのSHA-256をGit管理外の
  `artifacts/ocr-models/manifest.json`へ記録。通常の読み取りではローカルモデルを明示。
- `paddle.utils.run_check()`でCPU動作確認に成功。

モデル準備の再実行は既存ファイルを使い、再ダウンロードしない。
合成画像は、インターネットへのsocket接続を例外にする検証用設定を子プロセスへ継承しても
推論・候補抽出に成功した。実画像や原文は外部へ送信せず、Git管理外へ保存する。

## 実画像の先行確認（レビュー修正前の記録）

ユーザーが`data/valid/raw/`へ配置した3枚を使用。画像のファイル名・店舗名・住所・
会員情報・OCR原文は本記録に含めない。結果と人による対応付けは
`artifacts/ocr-evaluation/`へ保存する。

| 識別子 | 画像 | 推論時間 | 文字ブロック | 正解商品行 | 抽出候補 |
| --- | --- | --- | --- | --- | --- |
| receipt-01 | 1687×3000px JPEG | 190.55秒 | 78 | 17 | 17 |
| receipt-02 | 1687×3000px JPEG | 183.38秒 | 56 | 1 | 1 |
| receipt-03 | 1687×3000px JPEG | 185.04秒 | 93 | 22 | 22 |

画像と候補を目視で1対1に対応付け、計40正解商品行に対して40候補・40対応。
行抽出の通算適合率・再現率はともに100%。数量の補足行は独立した商品行として数えず、
同じ商品名でもレシート上の別行なら別の正解行として扱った。
文字修正が必要な行は31/40行（濁点・長音等の修正を含む）。この値は文字認識の正解率ではない。
今回はこの3枚を見て抽出規則を調整した結果であり、独立した評価画像での精度を示すものではない。

店舗は2店舗、画像は3枚のため、集計の`accepted`は`false`。
全画像300秒以内と30商品行以上は確認できたが、3店舗・5枚以上の基準は未達。
追加の画像での評価は[課題 #3](https://github.com/cake2357/house-account-app/issues/3)へ引き継ぐ。
ローカルの`receipt-XX.json`は初回推論記録、`receipt-XX-final.json`は同じ原文に
改善後の抽出を適用した記録。`review.json`が正解行の対応付け、`score.json`が集計結果。

初回抽出では見出し・数量行・会計欄が混入したため、
[課題 #4](https://github.com/cake2357/house-account-app/issues/4)として記録し、
傾き補正、明確な合計欄からの購入明細範囲の特定、数量・値引等の全体一致による除外を追加した。
商品名に含まれる「合計」等の部分一致では除外しない。
当時の抽出規則では購入明細の開始位置を推定していた。レビュー後の規則と再集計は次節に記載する。

商品行の対応と、文字の誤りは別の指標とする。誤認識された濁点等は人による修正が必要。
名称の推測・自動確定・タグの自動割り当ては行わない。

## レビュー修正後の再集計

[レビュー](https://github.com/cake2357/house-account-app/pull/5#pullrequestreview-5721138289)の
2件に対応し、先頭位置・数量行との位置関係による開始位置の推定を除いた。
判別できない価格なし行は先頭から要確認候補に残す。
終了位置は合計ラベルと金額からなる行全体の一致で判定し、
分割ブロックから結合した「合計 満足パン」等の商品名では終了しない。

保存済み3枚のOCR原文に修正後の抽出を再適用し、既存の目視対応表で再集計した。
OCR推論・画像との再照合は実行しておらず、推論時間は初回記録の値を引き継いだ。

| 識別子 | 正解商品行 | 抽出候補 | 既存の対応を保持 |
| --- | --- | --- | --- |
| receipt-01 | 17 | 25 | 17 |
| receipt-02 | 1 | 8 | 1 |
| receipt-03 | 22 | 35 | 22 |

通算40正解行・68候補・40対応、適合率58.8%・再現率100%、文字修正31/40行。
既知の商品行はすべて保持した一方、不明な見出し等も残るため、適合率80%以上の基準は未達。
サンプル数の不足に加えて適合率も未達であり、`accepted`は引き続き`false`。
候補精度の改善は[課題 #6](https://github.com/cake2357/house-account-app/issues/6)、
独立画像での最終評価は[課題 #3](https://github.com/cake2357/house-account-app/issues/3)で管理する。

再適用結果はGit管理外の`receipt-XX-review-5721138289.json`、
`review-5721138289.json`、`score-review-5721138289.json`へ保存した。
前節の`*-final.json`と`score.json`は当時の記録として保持している。

## 自動検証

以下はローカルで成功。工程0コードのGitHub Actionsでも依存構築・Ruff・整形・mypy・pytestの成功を確認。
結果は[PR #5](https://github.com/cake2357/house-account-app/pull/5)にも記録する。

```sh
uv sync --locked
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked mypy
uv run --locked pytest
uv build
```

固定OCR結果による66テスト。商品行・価格分離・同名商品の別行・低信頼度・傾き・
合計欄の境界・数量行・文字の部分一致による誤除外・モデル準備の再利用と失敗時の回収・
原文の先行保存・対応付けの不正や二重使用・通算精度の算出を検証した。
レビューの再現例と合計欄の表記違い9ケースを追加し、修正前は9件失敗、修正後は全件成功した。
OCRの実推論・モデル取得は通常のpytestやCIでは実行しない。

同梱スキルがRuffの対象に入り失敗する問題は
[課題 #2](https://github.com/cake2357/house-account-app/issues/2)へ記録し、
`.agents`のみをRuff・mypyの探索対象外にした。アプリとテストの検査は継続する。
